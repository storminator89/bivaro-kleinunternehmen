## Annual-context API v1

Tenant-owned `AnnualBusinessContextRevision` rows are separate from Settings. Each row is a complete snapshot with an owner-global monotonically increasing revision:

- `contextYear` (1901–9999); `effectiveFrom` is a valid date **in that year**, meaning validity of these context data only, not tax status.
- `foundingYear`: known year no later than context year, or null/unknown.
- `previousYearTurnoverCents` and `previousYearExternalTurnoverCents`: canonical nonnegative integer-cent strings (at most 16 digits), or null/unknown. They describe `contextYear − 1`. The external figure is the portion already included in total turnover but recorded outside Bivaro, not additional revenue. Null total with known external remains unknown total. A known external amount cannot exceed a known total. Founding in context year cannot coexist with positive prior-year turnover.
- `completeness`: `UNKNOWN`, `PARTIAL`, `COMPLETE`. COMPLETE requires all three founding/turnover/external fields known, including explicit zero where appropriate. It remains a user assertion, never VERIFIED.
- `sourceNote`: 1–200 trimmed plain-text characters, no control characters; rendered as text, not HTML. `declaredAt` is the server time; DTO/backup provenance is fixed `USER_DECLARED`. No source note or numeric amount is copied into the mutation audit.

Authenticated `GET /api/settings/annual-context` returns `{version:1, revision, history}` in ascending revision order. An empty history means no annual declaration, not confirmed completeness. `POST` requires the complete snapshot plus `{version:1, expectedRevision, declaration:true}`. Successful append returns 201 with `saved`. Transactional latest-revision compare + unique owner/revision reject stale and concurrent tabs with 409. Audit and append commit atomically. At most 1,000 revisions per tenant are accepted; reaching the bound returns 422 rather than silently truncating history. SQL triggers reject row updates and deletes.

A later declaration may correct an earlier declared validity date. It appends a snapshot and never edits its predecessor. The UI shows the per-year full revision history and the global saved revision; it does not claim a legal regime timeline.

## Backup / restore v3, standalone schema identity

The backup envelope remains v3. Standalone schema identity is `20261021070000_add_annual_business_context`; migration creates only this table and its owner relation/indexes/triggers. Previous review-draft schema `20261021054000_add_purchase_review_drafts` and earlier explicit identities remain supported with their original capabilities. All real new snapshots emit `annualBusinessContextRevisions` with API-v1 revision data and manifest coverage/hash. Absence in a legacy source means no source declarations, never confirmed empty target data. Optional absent sections remain accepted on the current identity for backward-compatible programmatic empty snapshots. Legacy v2 and pre-context v3 cannot carry nonempty annual histories.

Restore validates strict version/provenance, every field, contiguous revisions starting at 1, full timestamps and manifest integrity. Restores adopt the authenticated target owner, never a backup-supplied user ID. Empty targets may import the complete history. Existing targets accept only identical shared revision prefixes, appending any additional source revisions. A shorter or absent source history preserves all newer target declarations and emits an explicit warning. A divergent shared prefix fails closed **before any target data changes**. This rule applies equally to merge and overwrite: neither mode deletes or replaces annual context. No approval API is replayed.

**Integration dependency:** parallel manual-photo approval uses separate schema `20261021061000_add_manual_photo_approval` and `PurchaseDocument.reviewedSourceSnapshot`; that validator is not in this standalone baseline. This branch deliberately rejects that identity. A recomputed manifest under a recognized standalone 070000/054000 identity cannot launder nonnull `reviewedSourceSnapshot` evidence: both manifest validation and restore preflight reject it before any file resolver or target mutation. A strict current scalar-field allowlist also rejects unknown future source metadata rather than silently dropping it; an absent/null reviewed snapshot remains compatible. No manual-photo parsing or approval capability is added. Any eventual combined branch must use a **new, unique combined schema identity**, preserve explicit 054000/061000/070000 capabilities and test that no reviewed source snapshot is dropped and no annual history is erased. Never publish standalone and combined capabilities under the same schema identity. No EÜR2026 adapter/layout content is included.

Annual history is included only in JSON/full backups, not accountant/EÜR exports. Backup coverage does not mean fiscal certification.

## UI and operational limits

The optional section reuses the current paper/ink/green design, with one-column mobile fields, descriptive null/zero and external-share labels, accessible labels/errors and keyboard-operable history. Save errors preserve typed values; a revision conflict disables saving until the user explicitly loads and compares the latest history. Reload/latest can preserve typed values, but never marks them saved. Dirty close/internal-link navigation asks before discard; browser reload uses beforeunload; Back/navigation is explicitly described as not saving. Cancel changes neither annual persisted data nor minimal settings. No browser persistent storage is used.

Account lifecycle was checked: current `DELETE /api/users/[id]` deactivates the User and revokes API keys; it does not cascade-delete business data. This behavior remains supported with annual history present. Existing bootstrap test `user.deleteMany` operates only on its independent empty fixtures. Application/database immutability is not a promise of indefinite legal retention or protection from privileged database replacement; any future physical erasure/retention feature needs a separately reviewed policy and migration.
