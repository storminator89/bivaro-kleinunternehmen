# Optional receipt capture (implementation, not deployment acceptance)

AI only creates **unreviewed purchase-document suggestions and review drafts**. It never creates an Expense, Income, payment, selected Supplier or tax declaration. Payment date and business purpose remain empty unless supplied by a person. The original immutable tenant-owned bytes, SHA-256 and download remain authoritative. Financial posting still requires the existing independent explicit original/buyer/payment approval workflow; AI cannot authorize it. Ordinary PDFs without embedded XML may have draft suggestions, but this feature does not broaden the existing financial-approval formats.

## Consent and bounded provider transfer

Provider configuration and the automatic-new-upload option are disabled by default. Saving an enabled OpenAI-compatible vision provider is distinct from enabling automatic receipt transmission. A manual request requires explicit cost/data-transfer acknowledgment and **both** the numeric settings version and opaque random `configurationRevision`. The server rechecks configuration/automatic consent immediately before dispatch. No real credential, synthetic provider call, hosting change, external queue or new paid service is installed by this implementation.

A NEW supported upload is archived and deterministically parsed first. Successful XML (including embedded invoice XML) always wins; raw XML is never sent to AI. Only an explicitly opted-in NEW unstructured original triggers optional analysis. Upload replay, exact-original duplicate, page load and status polling cannot create a paid request. Automatic analysis is request-bound: the original is durably stored before analysis, but the initial upload HTTP response waits for the bounded attempt. An AI failure is separate from upload success and never causes an invisible retry.

## Input and output limits

- JPEG/PNG: existing archive validation already checks signature, single frame, <=24 megapixels, <=12,000 pixels per edge; AI input <=6 MiB. Original bytes are sent as a data URL, never as a model-controlled URL.
- PDF: <=6 MiB, one to four **complete** pages. Existing Ghostscript plus official Debian `util-linux`/`prlimit` run in a private 0700 temporary directory, input0600, native address-space512MiB/CPU15s/file2MiB/open-files64, wall20s and bounded diagnostic output. Ghostscript `-dSAFER`, stop-on-error/warning, fixed850x1100 JPEG rendering. A fifth rendered page detects over-limit PDFs; no first-four-page truncation is submitted. Missing/failing renderer, encryption, zero/incomplete/oversized output fail before provider dispatch. Cleanup runs on success/failure. The user's computer is not configured or modified.
- Provider request: one attempt, <=12MiB, timeout30s, <=64KiB response, <=32KiB assistant content, <=8192 tokens, no redirects/retries/fallback/tools/remote image URLs. Compatibility and vision support depend on the saved provider/model.
- Extraction: exact closed JSON schema, <=30 positions, mandatory `lineItemsComplete` true/false/null. False/null explicitly warns incomplete; true is a model claim, not verification. Output cutoff/non-stop completion fails closed in transport. General unreviewed warning always remains. Unknown dates/currency/fields remain null. Money is a bounded non-negative decimal string, exact arithmetic uses bigint cents, no numeric/scientific/negative/subcent coercion. Invalid dates, currencies, unknown schema fields, oversized arrays/text and invalid JSON fail. Netto+tax/gross inconsistencies block automatic amount capture. Receipt instructions are inert text, not executable instructions.

## Durable lifecycle and concurrent changes

`PurchaseDocument.aiExtraction` is bounded v1 evidence with <=16 attempts for that original. Identity binds tenant-owned original hash and opaque provider configuration revision; numeric version is only a CAS precondition. Durable DB-CAS claiming plus bounded app processing slots single-flight concurrent/reloaded requests. States are queued/running/completed/failed/unknown. GET CAS-persists expired queued/running leases as terminal unknown without launching paid work, then aborts matching local requests. Completion independently rechecks the persisted deadline in its transaction, so polling is not required to reject a late reply. A single overall90s deadline signal/race spans preparation and provider work, reaches the isolated PDF child, and prevents predispatch work after expiry; render20s/provider30s remain stricter component limits. Terminal-state persistence/cleanup still awaits bounded database transactions;90s is the extraction eligibility/work deadline, not a promise that database outage cleanup always completes within an HTTP SLA. No timer/restart path resumes a request. Explicit retry is required for failed/unknown, with new cost acknowledgment; completed same-config results are reused. Provider possibly-dispatched timeout/network/refusal/invalid envelope are unknown. Invalid structured assistant output is failed after a possibly charged response, never automatically retried. Cancellation is unknown and can still have been charged.

Automatic draft fill requires an absent draft, unchanged source revision, REVIEW and no linked expense. A concurrent manual draft, supplier selection, reparse, dismissal or approval never gets overwritten. Completed suggestions remain separately reviewable when manual edits win. Free explicit apply merges only empty supplier/number/invoice-date/amount fields after revision checking; it does not require a live provider or cost checkbox. Closing a source freezes active attempts as unknown in the explicit closure transaction, so a late callback cannot rewrite BOOKED/immutable/manual evidence or a dismissed source. Original approval snapshots remain append-only.

`aiDraftProvenance` distinguishes AI_UNREVIEWED from AI_USER_EDITED. Human photo approval retains the original manual source snapshot and additionally `aiApprovedSnapshot` with AI-origin evidence plus the human-confirmed saved draft, not AI authority. Inbox projections never select full `aiExtraction` or `aiApprovedSnapshot` JSON; full bounded evidence is owner-scoped detail/status only. No raw model response, prompt, key, endpoint or provider exception enters financial audit logs.

## Backup

Schema identity `20261021091000_add_ai_receipt_extraction` explicitly includes combined manual-photo/annual-context/AI capabilities. Older identities reject non-null AI evidence rather than dropping it. Full backups preserve evidence and original integrity; restored queued/running attempts become unknown and never auto-run. Provider settings/ciphertext are wholly excluded; ordinary business restore does **not** clear/delete/enable/change an existing target provider configuration/key. New targets set up their own provider. Opaque configuration revisions prevent source evidence masquerading as the target's current configuration.

## Verification boundary

Focused automated tests use synthetic originals and a mocked provider only; no actual endpoint/key/payment is used. Native PDF process tests mock execution and verify limits, all-pages rejection and cleanup. No native full build or browser run in this lane. Published-site journeys and integration typecheck are coordinated separately; this document is not a deployment or user-acceptance claim.
