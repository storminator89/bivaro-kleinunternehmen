## Provider interfaces (v1)
`lib/ai-provider/types.ts` browser-safe DTO:
`AiProviderSettingsDto = { enabled:boolean; autoAnalyzeNewUploads:boolean; baseUrl:string; model:string; hasKey:boolean; version:number; configurationRevision:string; encryptionAvailable:boolean; configured:boolean }`.
`AiProviderSettingsInput = { enabled:boolean; autoAnalyzeNewUploads:boolean; baseUrl:string; model:string; expectedVersion:number; keyAction:'keep'|'replace'|'remove'; apiKey?:string }`.
GET `/api/settings/ai-provider` -> DTO, no key/ciphertext fragments. PUT same -> DTO, authenticated tenant-scoped, CSRF + 16KiB body. Optimistic version; mismatch 409. Endpoint/model changes with existing key require replace/remove, preventing accidental transfer of old key to new destination. Key remove disables feature and automatic analysis. Disabled default, auto default false. Enabling auto requires enabled+configured. Empty keep never clears key.
POST `/api/settings/ai-provider/test` body `{ expectedVersion:number, expectedConfigRevision:string, acknowledgeCost:true }` -> `{ok:true}`. Tests SAVED config only; both numeric version and opaque revision must match before decryption or DNS/network, explicit synthetic prompt, no receipt. Requires enabled config and cost acknowledgment; no auto invocation. Rate-limited. Provider errors static/redacted. UI must state possible costs and show external original-data destination.
Server `lib/ai-provider/settings.ts`: `getAiProviderSettings(userId)`, `saveAiProviderSettings(userId,input)`, `resolveAiProviderConfiguration(userId,expectedVersion?,expectedConfigRevision?)` returns runtime `{baseUrl,model,apiKey,version,configurationRevision,autoAnalyzeNewUploads}` or throws `AiProviderError` with static message + code/status/requestMayHaveBeenSent. Runtime secret only server import.
Server `lib/ai-provider/transport.ts`: `requestAiCompletion(config, {messages: AiChatMessage[], maxTokens?:number}, signal?) -> Promise<string>` ONLY returns assistant content string (not parsed/validated accounting fields). Messages are role system/user with text or data URL image parts; no tools/URLs. Extraction validates strict final JSON schema and builds deterministic prompt; passes trusted bytes via data URLs, never model-supplied URLs. Provider call single attempt, timeout30s, 12MiB request, 64KiB response, content32KiB, maxTokens<=8192, no redirects/retries/fallback. `store:false`, stream:false. OpenAI Chat Completions subset, model vision capability user responsibility; no universal vendor compatibility promise.

## Exact SSRF policy
HTTPS by default; reject userinfo/query/fragment/control chars, invalid host/path. Append `/chat/completions` to base URL (e.g. https://api.openai.com/v1). Reject localhost/.local/.internal names and all non-public/special IPv4, IPv6 outside global unicast, transition/tunnel ranges. Resolve all A/AAAA and reject any non-public answer. Pin selected address at HTTPS connection via custom lookup (TLS verifies original hostname). No redirects (including same-origin). Public self-hosted HTTPS works normally. Private/self-hosted HTTP(S) requires operator-only env `BIVARO_AI_PRIVATE_BASE_URLS`, JSON array of exact normalized base URLs (scheme+host+port+path), never tenant override. HTTP is supported only for exact operator-allowlisted URLs; its key and receipt bytes cross the internal network unencrypted, so operators must provide a trusted isolated network/reverse proxy. Such entries explicitly allow private resolved IPs, still TLS verification and address pinning; no TLS verification exception. Operator is responsible for trust/egress of allowlisted private endpoint. Config save does syntax validation; DNS validation occurs each call before authorization leaves process.

## Secrets, backup, audit
Reuse existing SMTP pattern: AES-256-GCM key derived from NEXTAUTH_SECRET using distinct AI context plus tenant AAD. Missing/short runtime secret fails closed; no plaintext/environment provider-key fallback. Context rotation requires reconnect. Opaque configurationRevision UUID changes every save/reset; integer version is only a UI optimistic-concurrency guard. Provider config and ciphertext excluded entirely from business backups; no imported secret reuse on restore. Provider configuration remains entirely target-owned during restore: ordinary restore must not delete/clear or import an existing target configuration. New targets have no provider config and require reconnect; existing target configuration remains outside imported business data. Imported extraction provenance is compared against the current opaque configurationRevision. Audit only event, operation, enabled/auto flags/version; never baseUrl/model/key/provider response/prompt.
